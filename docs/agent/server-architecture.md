# 后端与服务端架构

> 从 `AGENTS.md` 拆出的按需文档，原文逐字保留。只有动到本域时才需要读它。

**Interchange 的依赖方向是 `server → interchange → core`**，它自己不含 Tauri 也不含 axum。导入 / 导出的**编排**（取内容、折成线形状、落库、产出文档）住在 `crates/simple-post-server/src/interchange_api.rs`，**不是**在 Tauri command 里 —— 这是 dual-transport invariant 的直接后果：那一层若写在某一侧，另一侧会静默少一半。四个薄壳入口两处都有（`src-tauri/src/commands/interchange.rs` 与 `web_api/routes/interchange.rs`），它们都只调 `interchange_api` 的四个函数。`interchange_api::import_commit` 走 `commit_in_tx` 而不是 `commit`：环境必须与树同事务，而 `with_tx` 闭包拿不到第二个连接（`BEGIN IMMEDIATE` 会自死锁）。

**项目与资源树节点的创建编排也住在 server crate.** 建项目、建节点这两段编排过去各写一遍：Tauri 命令在 `src-tauri/src/commands/{projects,nodes}.rs`，REST 路由在 `crates/simple-post-server/src/web_api/routes/{projects,nodes}.rs`。两边各拼一次那一行、各自决定 id 归谁铸、各自推导 `root_id`，于是同一个问题有两个答案，而没有一处会提醒它们分叉了。现在两段编排住在 `crates/simple-post-server/src/project_api.rs` 里，两侧薄壳只负责**线格式**：REST 侧解析两种 body 形状（`POST /api/projects` 的 `{name, opts}` 与打平的 `Project` 两种形状都还在用）、`ensure_server_id` 补 id，Tauri 侧把 `kind` 字符串解析成枚举。MCP 侧**不在**这一层：它的 `project_create` 走 `core::spec` 的「按名找或建」（带 `if_exists`），与这里的「照单新建」是两种契约；按项目的权限门在 MCP 那条路上管，`project_create` 刻意不走——项目还不存在，没有归属项目，也就没有可套用的存档权限。回归网分两层：`crates/simple-post-server/src/project_api_test.rs` 是行为用例，`crates/simple-post-server/src/project_api_shells_test.rs` 里的 `both_transports_call_the_shared_layer` 读四个薄壳的源码，要求它们都调 `project_api`、都不再自己拼那一段落库，且 REST 侧那两个收 `Json<Value>` 的薄壳都调 `ensure_server_id(`。

**Tauri 为什么要拆开。** `src-tauri` 无条件链接 `tauri`，于是它的 Linux 构建会拖进 `libwebkit2gtk` / GTK / X11 —— 而跑 `serve-web` 的容器只需要这个 GUI 却显示不了它。服务端那一半因此搬到 `crates/simple-post-server`，依赖只有一个方向：`simple-post (Tauri) → simple-post-server → simple-post-mcp → simple-post-core`（server 转发 mcp crate 的 spec / dynamic 操作，故 mcp 夹在 server 与 core 之间）。三条后果要遵守：

1. **`gui` feature 默认关闭。** 它只把那三个收 `AppHandle` 的守护进程动词（`ensure_started` / `start` / `restart`）接回来，让它们能往 webview 发 `daemon://crashed`。`src-tauri` 打开它，镜像构建不打开。**不要**为了「多复用点代码」把它挪进 `default` —— 那正是这个 feature 要避免的失败。
2. **线上 DTO 不属于 Tauri。** `McpStatusDto`、`CreateEndpointDetailOpts`、`RestartResult` 这些住在 `simple_post_server::dto`，`http_config.rs` 放着两者共用的读写助手。REST 路由直接用这些类型：`web_api/routes/mcp.rs` 写的就是 `crate::dto::McpStatusDto` 与 `crate::dto::RestartResult`，不抄第二份形状。`src-tauri/src/commands/dto.rs` 是 `pub use` 的兼容面，不是定义处 —— DTO 再落回那里，server 就又和 `tauri::State` 绑上了。
3. **桌面上的 `simple-post serve-web` 照常能用**，它转发到同一份实现，故 `npm run dev:split` 与文档里的局域网用法不会退化。只有一份实现，不是两份。

**CLI 模式**（`src-tauri/src/main.rs`，clap）：默认 → Tauri GUI；`mcp` → 内置 MCP 守护进程；`mcp-proxy` → 拒绝运行并指向独立的 `simple-post-mcp` 二进制（退出码 2）；`serve-web` → 无头 REST + 静态 SPA。

**CRUD 链路** —— 组件 → Zustand slice（乐观更新）→ `invokeCmd()`（`src/lib/tauri-commands.ts`）→ Tauri IPC **或** `fetch('<base>/api/…')` → `src-tauri/src/commands/`（桌面）/ `crates/simple-post-server/src/web_api/`（浏览器）→ `simple_post_core::db` → `store.db`（WAL）。

Dev split: Vite `5173` proxies `/api` to axum `4173`. It does **not** proxy `/mcp`: that endpoint is the MCP daemon's own port, which in development is assigned by the operating system, so the proxy has no way to know it.

**A duplicated endpoint lands right after the original.** `db::nodes::duplicate` reads the same parent's siblings in display order (`sort_order` ascending, `id` ascending), compresses them into the slots `0..N`, and inserts the copy into the slot right after the original. Compressing first is what makes the copy land in the right place. Shifting only the siblings that sort after the original leaves a sibling that shares the original's `sort_order` unshifted, and the read side orders by `(sort_order, id)`, so that sibling comes before the copy. Shifting a sibling whose `sort_order` is already `i64::MAX` overflows to REAL in SQLite, while the column reads back as `i64`.

**Async/concurrency.** tokio multi-thread runtime; `port_registry.rs` uses OS atomic file creation (`create_new`) to prevent multi-instance races.

**Reverse-proxy base path is a runtime fact, not a build constant.** `serve-web --public-base-path /sp` `nest`s the *entire* router under the prefix — `/api/*` and the two health probes all move to `/sp/…` together. (MCP 不在其中：它是守护进程自己的监听端口，不受这个前缀影响。) Two consequences that are easy to get wrong:

- `vite.config.ts` sets **no `base`**, so `vite build` emits root-absolute asset URLs (`<script src="/assets/index-<hash>.js">`), and every `WEB_ROUTES` path is root-absolute (`/api/projects`). Neither can be corrected at build time: in the container the prefix arrives as `SIMPLE_POST_PUBLIC_BASE_PATH` at **run** time and one image has to serve both shapes. So `static_files::shell_with_base` rewrites the shell's root-absolute `src`/`href` per response and injects `window.__SIMPLE_POST_BASE__`, which `readApiBase()` in `src/lib/tauri-commands.ts` reads to prefix API calls. **Never "fix" a base-path report by adding `base` to `vite.config.ts` or an nginx rewrite** — those reintroduce a second place that has to agree with the first.
- `/healthz` moves with everything else, so any probe hardcoded to the bare root 404s in exactly the deployment that sets a prefix. The image's healthcheck script reads the same env var for this reason.
- There is **no** `<base href>` tag, and there must not be one: it does not affect a root-absolute `src`, so it would look like a fix while changing nothing.

The regression net is `scripts/test-web-basepath.mjs`, which parses the served shell and actually requests every URL it finds. Its earlier version only asserted the *server* nested correctly (`/sp/api/…` → 200, bare → 404) and never looked at what the browser would ask for — which is how a deployment where the shell loaded and every API call 404'd could pass. Assert on the shell's real references and their content-types; `200 text/html` for a `.js` file is the ServeDir fallback, not an asset.

**A route named in `auth::is_public_path` but never registered answers `200` with the SPA shell.** The auth bypass list and the route tree are two places that have to agree, and nothing made them. `/healthz` sat in that list since the beginning (comment: "legacy, kept for backward compat") with **no `.route("/healthz", …)` anywhere** — so at the root it fell through to the ServeDir fallback and returned the index with `200 text/html`, and under a base path it 404'd. The container `HEALTHCHECK` passed the whole time, because it only grepped for `200 OK`. A probe that cannot fail is worse than no probe: **grep for the response body**, not the status line. Two assertions catch this class — `is_public_path` membership is not route existence, and a probe should assert the thing it is named after.

**OpenAPI.** `public_route_specs()` is defined in `crates/simple-post-server/src/web_api/spec/table.rs` and re-exported by `web_api/spec/mod.rs` (`pub use table::public_route_specs;`); that table is the single source of truth. **A route absent from the table counts as internal** — internal endpoints carry no version promise and stay out of the OpenAPI document, and their complete list lives in `web_api/spec/mod.rs` under 「internal (not in OpenAPI v1)」. `node scripts/dump-openapi.mjs` renders that table as an OpenAPI 3.1 document on stdout — pipe it wherever you want, e.g. `node scripts/dump-openapi.mjs > openapi.yaml`. The repository keeps no generated copy of that document: `docs/` still exists, but it holds only the UI screenshots under `docs/screenshots/`, and no `docs/openapi.yaml` is checked in.

**Traps a generated spec cannot express**, kept here now that `docs/http-api-reference.md` is gone (the `docs/` directory itself is still there — only that one Markdown file was removed):

- axum path params are `{id}` — the same form the OpenAPI spec itself uses, so a path copied out of `openapi.yaml` registers correctly and the old「spec 用 `{id}`、axum 用 `:id`，抄错就静默变字面量段」的分歧已不存在。两条 `RouteSpec` 与 `.route()` 共用同一批常量，改一处即可。
- The error envelope is stable: `{ "code": <snake_case>, "message" }`. The `code` is the part to branch on — treat it as the contract and `message` as human-facing text. Note the frontend currently does **not** branch on it: `invokeCmd` folds `code` into the thrown message (`HTTP 400 POST /api/… [validation] …`), so a caller that needs to distinguish "not found" from "denied" must parse the string or add a typed branch. Don't widen that string-formatting into more call sites.
- The auth matrix: `/api/healthz` and `/healthz` are always unauthenticated, as are `/assets/*` and the SPA shell — a browser cannot attach `Authorization` to a `<script type="module">`. MCP 那边有自己的一份名单：`/mcp/healthz` 与配置里那个挂载路径对应的 `<mount>/healthz` 免鉴权，其余 MCP 请求要口令（守护进程是 MCP 唯一的对外端点，故它必须和主服务器用同一道 bearer 闸；口令经环境变量 `SIMPLE_POST_WEB_PASSWORD` 传给那个子进程，不进命令行）。
- The openapi-diff comparison is the regression guard for any `web_api/` route-tree refactor: regenerate before and after, and a route that vanished shows up as a missing path rather than a failing test.
