# SSE / WebSocket / GraphQL 与 MCP 的协议边界

> 从 `AGENTS.md` 拆出的按需文档，原文逐字保留。只有动到本域时才需要读它。

**协议是端点的属性，不是另一种资源。** `endpoint_details.protocol` 取 `http` / `graphql` / `sse` / `websocket`，默认 `http`；`endpoint_details.graphql_json` 存 `{query, variables, operationName}`。两列都是纯增量（`ADDED_COLUMNS`），不 bump `SCHEMA_VERSION`。没有新建节点类型，工具表也不增加工具。**补丁里的 `protocol` 与 `graphql` 走 `double_option`**（`crates/simple-post-core/src/domain/resource.rs::EndpointDetailPatch`）：键缺席 = 不动，`null` = 回到 `http`（`graphql` 为清空），设值 = 写入——REST 与 MCP 对同一个 `null` 必须给出同一个结论。创建侧同样接住这两项：`POST /api/nodes` 的 `crates/simple-post-server/src/dto.rs::CreateEndpointDetailOpts` 有 `protocol`（未知取值在反序列化时报错）与 `graphql`（空 query 拒收）。

**GraphQL 是 HTTP 之上的组装规则。** 协议为 `graphql` 时请求固定 `POST`，`Content-Type: application/json`（用户自己写过这一行就就地改值），body 由 `{{var}}` 替换后的 query 与 variables 拼成 `{"query", "variables", "operationName"}`。variables 空白则不带这个键；非空时替换后必须解析成 JSON 对象，否则报校验错误。operationName 空白同样不带。对象键在发送前**递归排序**（数组里的对象也排序），因为组装有两份实现——`resolve_endpoint_with`（Rust）与 `prepareRequest`（TS）——两侧必须发出同样的字节，`fixtures/resolve-parity.json` 里的用例钉住这一点。query 本身不排序、不压缩。**组装期问题的唯一裁决是 `PreparedRequest.problems`**（`src/lib/http-build/prepare.ts`）：组装失败时 `body` 为 `null` 且 `problems` 里带一条 `{tab: 'graphql'}` 的问题，发送与建连入口（`src/features/http-tester/useRequestActions.ts`、`HttpTester.tsx` 的 SSE 建流）见非空就不发——不拦下就会发出一个没有 body 的 POST。格式校验是另一道门（`validateRequest`，`src/lib/request-validation.ts`），它只看替换前的模板，对含 `{{…}}` 的 variables **连形状都不判**：占位符可能整段引用一行 variables（`{{vars}}`）、落在值位置（`{"id": {{id}}}`）或键位置，替换后是否成立只有组装期知道（`src/lib/graphql.ts::variablesProblem` 的 `allowPlaceholders`，组装期传 `false`）。

**SSE 复用 HTTP 的组装，响应改为流。** 路由是 `POST /api/http/stream` 与 `DELETE /api/http/stream/{id}`；桌面端是 `stream_request` / `stream_cancel`。事件四种：`meta`（状态、响应头、实际请求头、contentType、最终 URL）、`chunk`（`seq`、`text`、本次原始字节数 `bytes`）、`end`（`durationMs`、`sizeBytes`、`truncated`、`reason`: eof/stopped/timeout）、`error`（kind: timeout/network）。超时作用于建连与块间空闲，超时以 `end{timeout}` 收尾而不是 `error`；`maxResponseSizeKb` 到顶以 `end{truncated:true}` 正常收尾；取消先发 `end{stopped}` 再关连接，不用 `abort`——否则调用方永远等不到收尾事件。跨块的多字节字符先缓冲再解码，`bytes` 报原始字节数，不是解码后的 UTF-8 长度。**SSE 与 WS 受同一条出站策略管辖。** `core::stream` 与 `core::ws` 都调 `http_executor::check_url`，策略取 `OutboundPolicy::from_env()`（`SIMPLE_POST_BLOCK_PRIVATE_NET` 为 `1` / `true` / `yes` / `on` 时拒绝回环、私网、链路本地与 CGNAT）；WS 侧先由 `crates/simple-post-core/src/ws.rs::check_ws_url` 把 `ws://` / `wss://` 映射成 `http://` / `https://` 再判，拒绝时发 `Error{kind:"protocol"}` 且不建连。两条 SSE 响应（`POST /api/http/stream` 与 `POST /api/ws/sessions`）都用容量 256 的有界通道 + `try_send`：队列满或接收端消失就结束会话（SSE 走 `stream::cancel`，WS 走 `ws::close`），并设 `x-accel-buffering: no`；WS 那条另有 `CloseOnDrop` guard，响应体被丢弃时关掉 core 里的会话（下行空闲时 sink 一次都不会被调用，没有它浏览器关标签后会话会一直留在注册表里）。

**SSE 不跑请求脚本。** 测试脚本要的是完整响应，而 SSE 的响应体没有终点。脚本字段仍随 body 收下（与 `/api/http/send` 同形），但不参与执行。调用历史由**渲染层**在收到 `end` 时写一行（与普通 HTTP 发送同一条路：`http_send` 从不写历史），服务端不写——两端都写会让一次会话出现两行。渲染层写的是未截断的正文，裁剪在落库时做：`crates/simple-post-core/src/db/response_history.rs::clip_body` 按 `RESPONSE_HISTORY_MAX_BODY_BYTES`（256 KiB）裁并置 `body_truncated`；面板本地不再切正文，只按同一上限标「已截断」徽标。历史行的 `contentType` 取 `meta.contentType`，服务端没报才回落到 `text/event-stream`。面板的「已接收」按每个 `chunk.bytes` 累加（`src/stores/slices/stream-slice.ts::sseEvents` 一次调用同时合并事件与加字节）。

**WebSocket 是独立会话，帧不落库。** 路由 `POST /api/ws/sessions`、`POST /api/ws/sessions/{id}/send`、`DELETE /api/ws/sessions/{id}`；桌面端 `ws_connect` / `ws_send` / `ws_close`。事件为 `state`（connecting/open）、`frame`（in/out、text/binary、`data` 或 `base64`、`bytes`、`at`）、`closed`（code/reason/at）、`error`。建连超时 10 秒。会话 id 由渲染层铸造，重连也由渲染层退避（1/2/4/8/16 秒，单次上限 30 秒，最多 5 次）；后端不自动重连，注册表只按 id 保存当前会话。**同一 id 再连一次会顶掉旧会话**：`crates/simple-post-core/src/ws.rs::connect` 先给旧会话投 `Close(1000)`，旧任务据此收尾；`finish` 只在 `same_channel` 成立时才从注册表摘除，故旧任务的收尾摘不掉新会话。渲染层因此每次重试都换 `sessionId`（`src/features/http-tester/stream/stream-sessions.ts::connectWs`）。读侧失败只发 `error`（`kind: network`）不发 `closed`——再补一条 `closed` 会被渲染层当成正常收尾覆盖连接状态。`send` 的 `kind=text` 带 `base64`、或 `kind=binary` 缺 `base64`，都报 `Validation`。

**WSS 与 HTTPS 用同一份 TLS 设置。** `core::ws::connect` 收合成后的 `TlsSettings`（`POST /api/ws/sessions` 的 `tls` + `tlsOverride`，桌面 `ws_connect` 的同名参数），三项证书路径都没配且没开 `acceptInvalidCerts` 时用内置 Mozilla 根；`caCertificatePath` 的证书**追加**到内置根之后（与 HTTP 侧同一语义，不是替换）；客户端证书与私钥**一起**给出时才用于 mTLS，只给一半会报错；`acceptInvalidCerts` 打开时信任链不参与。PEM 读入后同样先补 `END` 后面的换行（复用 `tls.rs` 的 `normalise_pem_boundaries`），否则下一个区块会被整段跳过。

**MCP 只发 HTTP 与 GraphQL。** `api_call_endpoint`、`api_run_request`、`api_run_collection` 遇到 `sse` / `websocket` 返回校验错误，说明要在应用内连接；集合批量跑时该条记为 blocked，不拖累其余端点。`api_run_request` 真的接受 `protocol`（四值，缺省 `http`）与 `graphql`：`graphql` 只在 `protocol="graphql"` 时允许，`sse` / `websocket` 在解析入参时就被拒。协议拦截对已存端点发生在**权限门之后**（`crates/simple-post-mcp/src/mcp/http_ops/call_endpoint.rs`）：无权限者连「这个端点是什么协议」都不该从错误文案里探测到。发送动词取解析出的 `ResolvedEndpoint.method`（`crates/simple-post-mcp/src/mcp/http_ops/send.rs::send_resolved`），GraphQL 的强制 `POST` 因此既落在线上也落在回执里。GraphQL 的空 query 报 `Validation`，且不再解析 HTTP body、不把它那份载荷的缺失变量记进报告（`crates/simple-post-mcp/src/variable_fill/resolve.rs::graphql_payload`）。`api_validate_endpoint` 对 SSE/WebSocket 出一条 issue，对 GraphQL 用**替换后**的文本判 query 是否空白、variables 是否解析成对象（`crates/simple-post-mcp/src/mcp/variable_fill.rs::validate`）。OpenAPI 导出跳过 SSE/WebSocket 并落一条诊断。**正文的 `example` 只对 GraphQL 端点导出**：`IrEndpoint.body_example` 仅由 `crates/simple-post-interchange/src/project.rs::graphql_projection` 填写（导入侧恒 `None`），`crates/simple-post-interchange/src/openapi/builder.rs` 把它写成 requestBody media 的 `example`；HTTP 端点即使有 `body.content` 也不写 example。导出成它真正会发出的请求：`POST`、由 `graphql` 组装的 JSON 正文（variables 原样嵌入，只为判「是不是 JSON 对象」解析一次，不重排键、不替换 `{{var}}`）、缺 `Content-Type` 时补 `application/json`；query 空白落 warn 且不写 example；variables 解析不成对象就只导出 query，并落一条诊断。`body.schema` **不再沿用 HTTP 载荷的 schema**：投影把 schema 置空，端点原来带着 schema 时落一条 info 诊断。导入侧不产生非 HTTP 协议（IR 没有协议字段）。Postman 方向目前只有导入。

**`tauri::ipc::Channel` 只出现在 `src-tauri`。** `simple-post-core` 与 `simple-post-server` 的事件出口是普通回调（`StreamSink` / `WsSink`），桌面命令在 `commands/stream.rs` 里把它接到 Channel 上。把 Channel 类型带进 core 或 server，web 构建就没有它。
