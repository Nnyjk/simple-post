The two implementations each write the same rules, so only a shared sample can pin them together. That also constrains how a PR may be split: a sample and the two implementations that read it have to land in the same commit. Splitting a change by language leaves the middle commit holding a sample that one side can no longer read, and that commit's CI turns red.

- `docker/` — container deployment (issue #17): `Dockerfile`, `docker-compose.yml`, `docker-swarm.yml`, `docker-portainer.yml`, plus `Dockerfile.dockerignore`. The ignore file carries that name because the build context is still the repository root (`docker build -f docker/Dockerfile .`), and from there BuildKit reads the Dockerfile-specific sidecar `<Dockerfile>.dockerignore` — the `# syntax=docker/dockerfile:1.7` first line is what makes BuildKit (the only builder that honours it) mandatory. Compose runs as `docker compose --project-directory . -f docker/docker-compose.yml …`: without `--project-directory .` Compose takes `docker/` as the project directory, misses the repo-root `.env` and names the project `docker`, which renames the data volume. The Dockerfile's three stages are load-bearing: the **runtime stage installs no packages at all**, which is only true while `simple-post-server` stays Tauri-free. Both yml files use `image:` (never `build:`) and omit a top-level `version:` so one shape feeds `docker compose up` *and* `docker stack deploy`. In the swarm file `deploy.replicas` is pinned to `1` on purpose — the store is a single-writer SQLite file in WAL mode, and WAL's `-shm`/`-wal` sidecars only work on one filesystem. **That covers concurrency, not placement**: the volume has the `local` driver, so a reschedule onto another node would find no volume, get a fresh empty one, and start on a blank database. The `placement` constraint below the replicas block is what closes that hole, and it is on by default for that reason — `replicas: 1` is frequently mistaken for a substitute, and it is not. The image tag is `${SP_IMAGE:-simple-post:local}` because Swarm pulls the name written in the spec on every node; a bare local tag exists on one machine only.
